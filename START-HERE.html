IDW Voice MIDI Studio 4.1

From microphone to a playable instrument — build, connect and verify.

If this folder contains BUILD-WINDOWS.cmd, it is the source package: build it using section 1. If it contains Run-IDW.cmd and a Windows folder, it is a compiled package: launch Run-IDW.cmd and continue with section 2. No GitHub changes or installed-plugin replacements were made.

1 · Build the upgraded Windows program

  1. Extract the entire ZIP to a writable folder. Open this guide from that folder.
  2. Install Visual Studio 2022 or its Build Tools with Desktop development with C++, an x64 MSVC toolchain, a Windows SDK and CMake tools. Install Git if fetching JUCE online. Microsoft’s CMake guide explains the tooling.
  3. Double-click BUILD-WINDOWS.cmd. It compiles the standalone program, VST3 and tests. Keep the window open to read any error. If your organization blocks PowerShell scripts, follow its approved script-running process.
  4. The default build fetches JUCE 9.0.2 and needs internet. With an existing checkout, run from PowerShell: .\scripts\build-windows.ps1 -JucePath "C:\path\to\JUCE".
  5. Only after build and tests succeed, a dated IDW-V4.1-Windows-….zip appears beside the source. Extract it and double-click Run-IDW.cmd. The program is under Windows\Standalone\IDW Voice MIDI Studio.exe.

Build failure? Send the final error lines. The source package cannot launch as an EXE by itself. Automated tests do not replace the microphone and DAW checks below.

2 · Prove the sound output first

  1. Close FL Studio initially. Plug in headphones and your microphone/interface.
  2. Run the standalone app. Open Options → Audio/MIDI Settings. Choose the actual microphone input and headphone output. Check Windows microphone privacy settings if the device receives no signal.
  3. Turn Preview sound ON and leave Hear microphone OFF. Press Test note. You should hear a short tone. This does not require singing.
  4. If there is no tone, check the selected output, interface/headphone volume and whether another app holds the device. Changing the noise gate will not fix this output test.

3 · Prove microphone detection

Stay quiet, press Calibrate noise, then sing a steady “ah.” Look for input level, accepted pitch and an increasing note count. The new status line explains common blockers. Calibration refuses digital silence, clipping or stopped audio. If it refuses silence, confirm the mic works by speaking, then retry quietly.

Avoid L + R initially: averaging opposite-polarity inputs can cancel them. Keep headphone monitoring under control. Do not lower the gate blindly when there is no input.

4 · Connect the VST3 to FL Studio

  1. Close the standalone app. Save your FL project and close FL Studio before replacing any installed VST3. Back up the previous complete bundle outside the scanned plugin folder.
  2. Copy the whole new Windows\VST3\IDW Voice MIDI Studio.vst3 folder to C:\Program Files\Common Files\VST3. This may require administrator permission. Do not copy just its inner binary. V4.1 keeps the same plugin identity; avoid duplicate old and new copies in scanned folders.
  3. Open FL Studio → Options → Manage plugins → Find installed plugins. Confirm the IDW interface says VERSION 4.1.
  4. Choose the interface driver in FL’s audio settings. On a free Mixer insert, select the microphone’s physical input. Confirm its meter moves. Load IDW as an effect on that insert.
  5. Open IDW’s wrapper settings and set MIDI Output port = 10. Load a VST instrument in the Channel Rack and set its wrapper MIDI Input port = 10. Choose a patch; confirm the instrument plays when clicked manually.
  6. Set the instrument to receive channel 1 or all channels. Keep MPE off initially. Turn IDW Preview sound off. Press Test note. You should hear the chosen instrument.
  7. Sing only after that test works. Match the synth bend range to IDW’s 2 semitones. A synth may ignore IDW’s pitch-bend-range messages.

Port 10 is a routing number. MIDI channel 10 is a different setting used for drums. Voice and Test note normally use channel 1. Many native FL instruments lack the VST wrapper input-port selector; start with a VST instrument that has it. See Image-Line’s wrapper reference and native-plugin limitation.

For the standalone-to-DAW alternative, use an existing virtual MIDI port, select it as the app’s MIDI output, then enable the same device as an input in FL Studio. IDW does not install a virtual MIDI driver. The VST3 method above avoids that requirement.

Press Copy diagnostics while the problem occurs and paste the report into chat. Also say whether Preview + Test note is audible and name your DAW, instrument and interface.

6 · Record and verify

  1. Set BPM to your project tempo. Record MIDI before singing, stop, export the .mid and import it into your instrument track.
  2. Export before closing the editor: the take is held in the editor, not a permanent session recording.
  3. Verify a steady note, a slide, a silence/release and Panic. Check both preset save/load and a DAW project reopen.
  4. For V4.1 specifically: stop host processing and expect AUDIO STOPPED; disconnect/mute the input and expect NO INPUT; disable Melody and Beatbox and expect TRACKING OFF. Restore normal settings.
  5. Do not intentionally overload headphones to test clipping. Feed a controlled test signal in a muted test project if checking the clipping warning.

Existing regression coverage includes pitch across sample rates and block sizes, scales, MPE, Panic, MIDI learn, capture, export, trained drums, preview and editor bounds. Those full tests still need to be run on this upgraded build. See current validation status.
