# V12.8 — choose a phrase and keep surrounding audio

This local source candidate adds **Take options > Use this phrase (keep surrounding audio)**. It uses the selected clip's trimmed time span as a replacement region on its track. Native installers, GUI inspection and AudioBox listening remain pending.

## Replace a line in a vocal

1. Save a backup of the song. Stop transport and open **Song Studio > Timeline**.
2. Keep your original take audible. Select the replacement recording from the Clip menu. If a previous whole-take choice muted the original, unmute the original first; phrase selection preserves existing mute states outside its region.
3. Set the replacement clip's **Trim in**, **Trim out** and **Start**, then **Apply clip / mix**. Start is where the trimmed phrase begins on the song timeline; trimming the source does not automatically move Start. For example, source 2–3 seconds placed at song time 2 seconds needs Trim in = 2, Trim out = 3, Start = 2.
4. Choose **Take options > Use this phrase (keep surrounding audio)**.
5. Put Edit cursor before the phrase and **Play cursor**. Stop and adjust if necessary.
6. **Undo edit** restores the entire phrase selection, including splits and mute changes. Trimming applied in step 3 is a separate earlier edit. Redo restores the selection. **Save song** keeps the result.

If the full replacement take should also remain available as an untrimmed clip, use Copy to cursor before trimming. Trims and splits share the original audio buffer; they do not erase source samples.

## What the edit does

The selected clip becomes audible. Each other audible clip on the same track is divided at the selected phrase's boundaries where necessary. Only the pieces overlapping that phrase become muted. Outside pieces retain their previous audio and outer fade ramps. Already-muted clips and other tracks remain unchanged. Track gain, pan, mute and solo still apply.

The selected clip retains its menu position; additional pieces appear at the end of the clip list. Muted pieces remain available for later selection or unmuting. Because clips are split, a full track can reach the 64-clip limit sooner. Undo/recovery retain the previous arrangement using shared source audio.

This is an initial manual comping workflow. It does not rank takes, automatically align performances, add crossfades or provide dedicated comp lanes. A sharp transition may click or sound unnatural: audition joins and adjust boundaries/fades manually. Selected-clip fades remain active and may produce a dip against muted competing audio.

## Rejected edits

The entire edit is rejected while transport is active, for invalid/empty phrases or phrases extending beyond 180 seconds, if it would exceed 64 clips on the track, if a new cut falls inside an existing fade, or if it would create a piece shorter than one source sample. Adjust boundaries or fades first. Rejection leaves the song unchanged.

## Compatibility and build

No new project format is required: the result uses the existing clip, fade and format-7 mute data, readable by V12.7. Earlier versions cannot read format-7 projects. Playback, recovery and WAV export follow the resulting clips and mute states.

From a Visual Studio 2022 C++ developer terminal with CMake installed:

```bat
cmake -S . -B build-v12.8 -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=ON
cmake --build build-v12.8 --config Release
ctest --test-dir build-v12.8 -C Release --output-on-failure
"build-v12.8\IDWVoiceMIDIStudio_artefacts\Release\Standalone\IDW Voice MIDI Studio.exe"
```

Configuration uses pinned JUCE, or pass `-DIDW_JUCE_PATH=...` for an existing checkout. Audio Lab packaging is separate. This source change does not update your installed Windows application.

## Validation

`IDWSongPhrases` covers all four tracks, surrounding audio and outer fades, track mixer preservation, shared source buffers, atomic undo/redo and recovery, project round trips, selected-primary clips, transport protection and rejected fade/clip-limit edits. Take and clip regressions cover the shared mute, persistence and export paths. Native UI, installer, plugin and hardware listening checks remain release gates.
