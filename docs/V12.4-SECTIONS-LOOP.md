# V12.4 — section markers and loop playback

This local source candidate adds named bar ranges and repeat playback to Song Studio. Use it to rehearse a verse, listen to a hook transition or compare arrangement edits. It is not yet a validated Windows installer; native GUI and AudioBox listening checks remain pending.

## Mark and rehearse a section

1. Open **Song Studio**. Set BPM and Bars in Beat controls. The existing meter is 4/4.
2. Open the new **Sections** tab beside Timeline.
3. Enter a name such as `Verse 1`, `Hook`, `Bridge` or `Outro`.
4. Enter **First bar** and **Last bar (included)**, then click **Add section**. For example, First `5`, Last `8` covers four complete bars, ending at the start of bar 9.
5. Select the marker from the section menu. **Play section** plays it once and stops at its end. **Loop section** repeats it until you press **Stop**, either here or in the main transport.
6. Open Timeline while it plays to see the playhead wrap. Section start markers appear there; crowded labels are skipped, while the Sections menu always shows complete names and ranges.
7. Stop before changing clips or markers. Make your edit and loop again to hear it. **Save song** keeps the markers with your audio and lyrics.

**Update section** applies name/range changes to the selected marker. **Add section** creates a separate marker. Play uses the saved marker values, so click Update after editing its fields. **Remove marker…** removes only the marker, after confirmation; audio and lyrics stay intact. Marker edits participate in the existing Undo/Redo history alongside track edits.

Up to 32 sections are allowed. Names can contain up to 64 characters; first/last bars must be in the range 1–64. Sections may overlap and names may repeat. Menu order is insertion order. Markers are navigation ranges, not audio clips or lyric headings.

## Tempo and song length

Markers follow bar numbers when BPM changes. Audio clips retain their existing positions in seconds and are not stretched, so check the arrangement after changing tempo.

A section must fit within the current Song Bars to play. If you shorten the song, markers beyond the end are kept but playback is rejected until you increase Bars or update the marker. The existing 180-second maximum still applies.

Playback uses the audio sample clock, with section boundaries rounded to sample positions. It can wrap within a processing block; the drum pattern and metronome restart at the section's song position each pass. Fractional-tempo boundaries are covered by automated tests.

## What looping does—and does not do

- **Play song** still starts the full song at bar 1. Section playback does not change that button's behavior.
- Recording still starts at bar 1 after the chosen count-in, requires an empty armed track, and stops at the song end. This is playback looping, not loop recording, punch-in or take comping.
- Playback starts immediately; the count-in applies only to recording.
- **Export mix WAV** always renders the full song once. It does not repeat or restrict the export to the last played section.
- Loop state is temporary. Opening a project does not start playback or restore an active loop.
- There are no automatic crossfades at loop boundaries. A cut through sustained audio can click; adjust the section or clip fades and listen. Synthesized drum tails are reset when the loop wraps.
- To switch sections, Stop, choose another marker and Play/Loop. Live section switching is not provided in this milestone.

## Project compatibility and recovery

Songs with markers use **format 6** and require V12.4. Formats 1–5 still open, with no section markers. Songs without markers retain earlier formats where possible. Use a new filename if you need to keep a copy compatible with an older installation.

Stopped-song recovery includes section markers. Undo/Redo retains the existing eight-state/audio-memory bounds and is not saved in the project. Permanent saves still require **Save song**. Recording in progress is not checkpointed.

## Build and run on Windows

Use the repository's Visual Studio 2022 C++ and CMake prerequisites. From a developer terminal in the repository root:

```bat
cmake -S . -B build-v12.4 -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=ON
cmake --build build-v12.4 --config Release
ctest --test-dir build-v12.4 -C Release --output-on-failure
"build-v12.4\IDWVoiceMIDIStudio_artefacts\Release\Standalone\IDW Voice MIDI Studio.exe"
```

Configuration fetches pinned JUCE; supply an existing checkout with `-DIDW_JUCE_PATH=...` when needed. Audio Lab packaging is separate. These source changes do not update your installed Windows copy automatically, and no V12.4 installer has been validated.

## Validation

`IDWSongSections` covers one-shot ending, loop sample order across processing blocks, fractional tempo, repeated drum/metronome behavior, transport edit locks, marker limits, Unicode names, undo, format-6 persistence, corrupt/truncated file rejection, recovery snapshots, full-song export, tempo changes, shortened-song bounds, older-file migration and recording isolation. Existing song, count-in, recovery, clip, fade and arrangement/arming tests also run. Editor/processor syntax is checked against available JUCE sources.

Before release: run the full native Windows/macOS builds, plugin and installer validation; inspect Sections and Timeline at minimum window size in all skins; listen through the AudioBox USB 96 when available. Check a verse loop, a hook loop, Stop, marker edits/undo, Save/Open, full export and return to normal recording.
