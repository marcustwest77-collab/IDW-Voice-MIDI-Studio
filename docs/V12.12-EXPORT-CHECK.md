# V12.12 — check the song before exporting

This local source candidate adds a background full-song level scan. Native GUI, installer, plugin and AudioBox validation remain pending.

## Run the check

1. Save the song and stop transport.
2. Choose **Export audio > Check full-song levels**.
3. Watch the percentage in Song Studio. You may keep editing or resume playback; the check uses the song state captured when it started. **Cancel check** stops it.
4. Read the completed report: Lead, Backing, Double, Ad-lib, Drum pattern and Full mix peaks are listed in dBFS before the output limiter.
5. If the mix is silent, check the arrangement, mute/solo, gains and configured song length. If the limiter threshold is crossed, lower relevant levels and scan again.
6. Export when satisfied. The check is optional and does not block export or change levels automatically.

Only one background check/export runs per Song Studio panel. Closing/destroying the panel cancels and joins the worker. The report appears after a successful scan; cancellation does not publish a partial report. Reports are shown in a dialog and are not saved into the project.

## Understand the results

The scan renders the entire configured song at 48 kHz, from time zero to song end, regardless of the play cursor or loop selection. It includes clip trims/fades/mutes, track gain/pan/mute/solo, printed recorded effects, master track gain and the synthesized drum pattern. It excludes live microphone input, count-in and metronome cues. Offline checks do not change the live Timeline meters.

A silent mix means its measured peak is exactly zero; this is not a near-silence classifier. Individual silent tracks may be intentional. Opposing signals can cancel in the full mix even when individual tracks contain audio.

A threshold crossing occurs when either stereo channel exceeds the safety limiter's knee of 0.94 linear (approximately −0.54 dBFS). The report gives the first affected song time in seconds and the percentage of stereo sample frames affected, counting each frame once even if both channels cross. This measures threshold exposure, not gain reduction. The final exported waveform remains processed by the existing safety limiter.

These are sample-peak measurements, not LUFS, RMS, true-peak or streaming-service compliance checks. A report with no threshold crossings does not certify the mix's quality or loudness. Listen to the result. Later edits invalidate the earlier report; recheck before export.

## Build and run on Windows

From the repository with Visual Studio 2022 C++ and CMake:

```bat
cmake -S . -B build-v12.12 -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=ON
cmake --build build-v12.12 --config Release
ctest --test-dir build-v12.12 -C Release --output-on-failure
"build-v12.12\IDWVoiceMIDIStudio_artefacts\Release\Standalone\IDW Voice MIDI Studio.exe"
```

Configuration fetches pinned JUCE or accepts `-DIDW_JUCE_PATH=...`. Audio Lab packaging is separate. This source milestone does not update your installed application.

## Validation

`IDWSongMixCheck` checks silence and cue exclusion, per-track/mix peaks, low-level export parity, threshold-frame count and first location, track mute, cancellation preserving prior results, worker snapshot isolation, transport protection and no live-meter pollution. Existing background-export tests check shared worker completion, cancellation and cleanup.

Before release: inspect the report dialog in all skins and at minimum window size, verify progress/cancel while editing, compare scan results against rendered WAVs on Windows/macOS, and complete native build/installer/plugin and AudioBox checks.
