# V11.2 native dictation — local candidate

Song Studio can now feed its existing microphone input to an optional local Vosk recognizer. You can speak a draft, review it, and append it to the lyrics stored in your song. This is source awaiting platform validation, not a verified installer.

## Windows / AudioBox USB 96

1. Open the IDW standalone app and select your working AudioBox driver, input and output in Audio/MIDI Settings. Use a 16–192 kHz sample rate. Verify IDW's input meter moves.
2. Select **Left / mono** for microphone input 1, **Right** for input 2, or **L + R** to average both. Dictation follows this selection and receives the raw input before tuning, effects, instruments and beat playback.
3. Open **Song Studio > Dictation**. An installed Windows Audio Lab normally supplies the speech engine/model automatically. Portable users must extract the entire package, including the sibling Audio-Lab folder.
4. If assets are missing, select **Speech runtime…** and choose `Audio-Lab/_internal/vosk/libvosk.dll`. Keep its companion DLLs beside it. Select **Speech model…** and choose `Audio-Lab/_internal/speech-model/vosk-model-small-en-us-0.15` (the folder containing `am`, not the `am` folder itself).
5. Choose **Start dictation**. Wait until **MIC ON** appears before speaking. Pause between phrases. The provisional “Hearing” line may change; completed phrases accumulate in the draft.
6. Choose **Stop dictation** and wait for the final phrase. Review the draft, then choose **Append to lyrics**. Switch to **Lyrics** to edit mistakes. Appending adds to the end of your lyric body and clears the draft only after success.
7. Stop song transport and choose **Save song**. Appending alone does not save to disk.

Dictation does not switch on audible microphone monitoring. You can dictate while Song Studio plays or records, but use headphones to avoid transcribing sound leaking from speakers. Speech recognition adds CPU load; audio tuning/recording remains the priority. If recognition falls behind, capture stops with a visible message and preserves the partial draft.

## What is local and what is temporary

- No second microphone device, cloud service, audio file or runtime model download is used by native dictation.
- Vosk model loading and decoding run on a worker thread. The audio callback only converts/copies samples into a fixed-capacity queue; no recognition or disk access occurs there.
- Dictation runs only after Start. Stop, PANIC, leaving the Song Studio panel, destroying its editor, or changing/stopping the audio device stops capture. A ten-minute limit also ends a session. Stopping may take time while the last phrase is decoded.
- Missing audio callbacks for three seconds stop the session with guidance to enable the audio device/host processing.
- Drafts remain in this processor's memory across panel reopening, but are not project data. Append and Save song before quitting. There is no crash recovery yet.
- New-song opening is blocked while dictation is active or a draft remains. Append or explicitly discard it first. **Discard draft…** asks for confirmation and leaves appended lyrics intact. The draft allows selecting/copying text if the lyric size limit prevents append.
- Title/lyrics size limits and song format 2 are unchanged from V11.1. V11.1 can read songs saved by V11.2. Original V11 format 1 also remains readable.
- Manual runtime/model selections last for this editor's lifetime. Reopening the app may require selecting custom asset locations again.

## Runtime support and limitations

Windows packaged Audio Lab assets are the initial target. Native recognition uses Vosk's C API and a compatible library matching IDW's architecture. Only select a trusted speech runtime: choosing a library loads executable code. On macOS, speech assets are not currently bundled; a compatible runtime (`libvosk.dyld` or `.dylib`) and model must be supplied manually. The `.so` runtime is available for source development on Linux.

The default model is offline English speech recognition, not sung-vocal transcription. Singing, music bleed, names and accents can produce errors; review the transcript. Audio Lab's voice punctuation commands are not yet implemented in the native panel. No voice cloning, new cloud processing or AAX support is introduced here.

## Build and validation

Use the [V11.1 Windows source-build instructions](V11.1-UNIFIED-LYRICS.md), substituting `build-v11.2` for the build directory. The CMake app version is 11.2.0. Build all targets and run CTest.

New automated checks:

- `IDWDictationQueue`: input selection, normalized-float to PCM conversion, clipping/nonfinite input, queue overflow, wraparound and concurrent ordering.
- `IDWNativeDictation`: a simulated Vosk library checks loading, start/stop, final results, cancellation while loading, duplicate-start protection and sample-rate changes. This is a transport/API contract test, not recognition accuracy.
- `IDWNativeSpeechSmoke`: a separate real-runtime test takes three arguments: runtime path, model folder, and official spoken-number WAV fixture. Windows CI runs it against the packaged Audio Lab assets before installer generation. The simulated library is never staged in installers.

Local queue and worker contract tests passed, and editor/processor/test source is syntax-checked against JUCE. The real Vosk gate, complete Windows/macOS builds, GUI appearance and physical AudioBox tests remain pending for V11.2.

Manual acceptance: test installed and portable discovery; missing/wrong-architecture assets; both AudioBox inputs; Stop while loading/listening; last-phrase preservation; simultaneous recording; PANIC; panel/editor close and reopen; device-rate changes; lengthy dictation; append at the lyric limit; save/reopen; and a CPU stress session. In a DAW, the host must actively process input audio. Use the standalone app for initial setup.

API reference used for the runtime bridge: https://github.com/alphacep/vosk-api/blob/master/src/vosk_api.h
