Test remote recording, step by step

Use two IDW windows on one Windows computer. Window A controls recording; window B records and stores the take.

SetupFirst takePermission checksTroubleshooting
Before starting: use disposable projects and a build that passed the Windows network checks. Only B needs the microphone. Avoid opening the same exclusive audio device in both windows. This feature sends Arm/Record/Stop commands; audio, video, takes, mixer changes and project edits are not transmitted.

1. Start a private local room

Python must be installed separately. Open a terminal in the installed beta folder, normally %LOCALAPPDATA%\Programs\IDW Combined Studio Beta, or in the extracted portable beta folder. Run:

python -m pip install -r studio_sessions/requirements.txt
python studio_sessions/local_test_room.py

Keep the terminal open. It prints a server address, room ID and separate A/B tickets. Tickets expire after one hour or when the server closes. Keep them out of screenshots and messages.

  1. Open two copies of the IDW Combined Studio Beta timeline.
  2. In both windows, open IDW Connect → Remote Controller.
  3. Enter the same server address and room ID. Use the A ticket in A and the B ticket in B. Click Join in each.

2. Record a short take

  1. In B, add and select an empty audio track named Remote test. Select your microphone input and confirm a local recording plays back first.
  2. In A, click Request Control.
  3. In B, open My Permissions and choose Allow selected track. Granting permission alone must not start recording.
  4. In A, select Remote test and click Arm. Confirm B's track becomes armed.
  5. Click Record in A and speak a short phrase into B's microphone. Wait for the command result, then click Stop.
  6. In B, confirm the take is saved/imported and listen to it. For the AudioBox overdub check, load a beat and confirm you hear both beat and vocal through headphones.
Success means audible audio. A successful command message does not prove that a usable take was captured. Buttons disable while waiting for a result. If the connection fails, check B and use its local Stop.

3. Check permission boundaries

  • Before A requests control, B should show instructions instead of Allow buttons. Reopen My Permissions after a request arrives.
  • Each grant consumes its request. Request again to change permission or refresh the track list. A changed request requires reopening the approval dialog.
  • With selected-track permission, arm a second unapproved track in B. Remote Record must be denied completely.
  • Request again and allow all tracks. Test recording the approved armed tracks with available inputs. This permission also covers future audio tracks; request again to refresh the displayed list.
  • Revoke control while stopped. A's track list should clear and commands should disable.
  • During a disposable take, click Leave in A. In B, use local Stop and confirm the take is saved/imported.
  • Reconnect and confirm fresh permission is required. Opening a different project in B must also revoke permission.
  • Let permission expire, up to 15 minutes. A's controls should clear.

Closing the controller dialog does not leave the room. Use Leave to disconnect.

Testing from two computers

The local launcher accepts connections only on its own computer. Two-computer testing needs a configured HTTPS/WSS signalling server and separate room tickets. No hosted server is supplied with this beta. The browser video-room button is separate from this recording connection.
