# V11.3 — song and writing recovery

This local candidate adds automatic recovery checkpoints. It builds on the local V11.2 dictation work; neither milestone is a platform-validated installer yet. No microphone or AudioBox is needed to test recovery with typed lyrics or synthetic audio.

## What is saved

| Work | Checkpoint policy |
| --- | --- |
| Song title and lyric body | Approximately every 10 seconds when changed |
| Completed phrases in the native dictation draft | Approximately every 10 seconds when changed, even before Append |
| Beat, tempo, levels and recorded take | Approximately every 30 seconds when changed, while song transport is stopped |
| In-progress microphone recording | Not checkpointed; wait for Stop and a successful song checkpoint |
| Provisional “Hearing” text | Not checkpointed until the recognizer finalizes the phrase |

Recovery runs on a separate disk worker. A stopped song is copied into an independent snapshot before disk writing, so file I/O does not hold the live song engine lock. Large takes still need memory and disk space. A busy or unavailable snapshot is retried at the next interval. A normal processor shutdown finishes dictation and attempts a final checkpoint; it is not a substitute for Save song.

The footer in Song Studio reports checkpoint times and disk failures. **Save song** remains your permanent, named `.idwsong` project. Recovery never overwrites a user-selected project file. Recent changes after the last successful checkpoint can still be lost; disk/power failure cannot be guaranteed recoverable.

## Recover after an unexpected close

1. Reopen IDW and open **Song Studio**. Stop song transport and dictation.
2. Choose **Recover…**. Pick the entry by time, title and session identifier.
3. To restore the beat and recorded take, choose **Restore song**. Save current work first, and append or discard any pending dictation draft. Confirm replacement.
4. Writing can be newer than the full song checkpoint. Reopen **Recover…**, select the **same entry**, and choose **Restore writing**. This replaces only the title, lyrics and dictation draft, keeping the currently loaded beat/take. Confirm replacement.
5. Inspect Lyrics and Dictation. If needed, append the recovered draft to the lyrics.
6. Choose **Save song** and save a permanent project copy.

If the newest copy is unreadable, recovery tries the previous copy and explicitly reports that fallback. If neither copy can be read, current work stays intact. Restore never runs automatically on startup and always asks before replacing work. Recovered documents receive a new recovery identity so the source checkpoint folder is preserved.

## Storage and retention

Recovery files live below the operating system's user application-data directory in `IDW Voice MIDI Studio/Recovery`. On Windows this is normally `%APPDATA%\IDW Voice MIDI Studio\Recovery`. **Recover… > Open folder** reveals the location.

Each processor instance has its own session folder; each opened/recovered song has its own document folder. Within each document, IDW retains up to two writing JSON checkpoints and two `.idwsong` checkpoints. Writing JSON contains title, lyrics and draft text in readable local form. Song files contain audio and may be large (about 69 MB for 180 seconds of stereo at 48 kHz, per copy).

Old session/document folders are not automatically deleted. After saving and verifying permanent projects, you may remove unwanted old recovery folders using your file manager while IDW is closed. Recovery is local to this computer and does not sync or upload anything.

## Compatibility and remaining work

The `.idwsong` format remains version 2, compatible with V11.1 and V11.2. Original V11 format 1 can still be opened. Recovery files are separate from DAW state, plugin presets and Audio Lab's existing lyric storage.

There is no streaming crash-recovery recording, autosave to your named project, multitrack recovery or automatic merge of song/writing checkpoints in this milestone. Physical AudioBox and native speech accuracy checks remain deferred. The V11.2 real-Vosk CI gate is retained for a later approved push.

## Build and test

Use the [Windows build instructions](V11.1-UNIFIED-LYRICS.md), substituting `build-v11.3`. Build all targets, then run:

```powershell
ctest --test-dir build-v11.3 -C Release --output-on-failure
```

The new `IDWSongRecovery` test uses temporary directories, typed text and synthetic audio. Locally it passes:

- Writing and unappended draft checkpoints during recording, with full-song capture deferred.
- Stopped-take backup and sample-checked audio recovery.
- Previous-copy fallback for corrupt song and writing files.
- Invalid-checkpoint preservation of existing work.
- Separate document/session folders and unwritable destinations.
- Background requests and final writing checkpoints on normal service shutdown.

Editor and processor source also pass JUCE-header syntax checking. Full Windows/macOS builds and GUI validation are pending.

Manual checks without an AudioBox: type lyrics, wait for the writing checkpoint time, close/reopen and recover; edit a drum pattern, stop and wait for a song checkpoint; cancel every recovery confirmation; open two instances and confirm separate entries. On a disposable test project, force-close the app after a successful checkpoint and restore it. Check latest/previous fallback using copies of test recovery files, and confirm failure messages with an unwritable test directory. Do not use your only project copy for destructive tests.
