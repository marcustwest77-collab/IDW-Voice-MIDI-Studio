# V6.2 — portable Audio Lab

The tested Windows ZIP includes Audio-Lab/IDW-Audio-Lab.exe, Python runtime,
Basic Pitch model and ONNX dependencies. Extract the entire ZIP, then use
Run-Audio-Lab.cmd. Keep the Audio-Lab folder intact. No separate Python install
or model download is needed for local transcription in this edition.
Source developers can still use Companion/Setup-Transcription.cmd.

## Transcription controls

Choose a 16-bit PCM WAV (mono/stereo, 8–96 kHz, up to 10 minutes and 25 MiB).
Inspect levels first. Start with onset 0.5, sustain 0.3, minimum note 127.7 ms,
and the project's tempo (40–240 BPM). Lower thresholds detect softer notes but
can add false notes. Increase minimum note length to remove short artifacts;
decrease it for fast playing. Tempo writes the MIDI tempo map; it does not
quantize notes or time-stretch audio. Settings are saved in report.json.

Click Transcribe and choose an output folder. Import transcription.mid into a
DAW instrument track. Assign an instrument and enable track monitoring for
live native MIDI use; file transcription itself does not configure DAW routing.
Best results come from one instrument or isolated stems. This is offline file
polyphony, not live polyphonic microphone detection.

## Verification

scripts/package-audio-lab.ps1 builds the portable Windows executable and runs
its --self-test outside the repository with Python paths removed. The test
executes the bundled model on a synthetic chord, verifies overlapping MIDI
notes, and starts/closes the bundled Tk GUI. This is a packaging gate, not a
music-quality benchmark or a physical microphone/DAW test.
All existing native processor, synthesis, retrospective capture, scene and
plugin validation gates remain. No cloud account is used by these tests.

## Optional cloud voices

Kits voice conversion still needs a user account, API key, eligible voice model
and explicit approval for each upload. Voice training takes place in Kits.
No voice cloning model or cloud credentials are bundled with this download.
