# V12.7 — clip mute and take selection

This local source candidate lets you compare recordings without deleting audio. Windows/macOS installers, native GUI inspection and AudioBox USB96 listening tests are still pending. It does not update an already installed copy.

## Compare your takes

1. Open **Song Studio > Timeline** and stop transport.
2. Select the track and choose a recording from the **Clip** menu. The menu is useful when overlapping waveforms obscure older takes.
3. Open **Take options > Use this take (mute whole overlapping clips)**.
4. Place the edit cursor before the phrase and press **Play cursor**. Track gain, pan, mute and solo still apply.
5. Stop, select another overlapping clip, choose **Use this take**, and play again.
6. Use **Undo edit** / **Redo edit** to restore a previous choice. **Save song** keeps your selection with the audio and lyrics.

**Clip mute** immediately mutes or unmutes only the selected clip while stopped. It does not need Apply clip / mix. Muted clips appear dimmed with an **M**, and their menu entries say **muted**. Track mute remains a separate control that silences the entire track.

**Unmute this take and overlapping clips** enables the selected clip plus its directly overlapping neighbors. They will play together. It does not restore an earlier custom combination; use Undo for that.

## Exactly what selection changes

The chosen clip is unmuted. Other clips with a positive time overlap on that same track are muted in their entirety. Clips that only touch endpoints, disjoint clips, and other tracks retain their states. Overlap uses trimmed playback intervals, not the whole source recording, and does not propagate through chains of overlapping neighbors.

A longer old take is muted even in portions outside the selected take. Split/trim clips first if those portions should remain audible. This is whole-take selection, not automatic phrase comping, take ranking or loop recording. Take and mute edits require stopped transport.

Copy and Split preserve the source clip's mute state. Removing a first clip preserves the next clip's state when it is promoted. Imports and new Record cursor recordings start unmuted; existing takes retain their current mute settings. No source audio is changed. Track solo still suppresses other tracks even if all clips on the solo track are clip-muted.

Playback, recording backing, recovery snapshots and full-song WAV export use the same clip mute states. Export retains the existing song-length and mixer behavior. Headphones are still required to prevent acoustic backing bleed into the microphone.

## Project compatibility

Projects containing clip mute use `.idwsong` format 7 and require V12.7 or newer. Older versions reject them; keep a backup before moving between versions. V12.7 reads versions 1–6 with clips initially unmuted. If every clip is unmuted, saving uses the earliest existing format needed for the other song features. Invalid or truncated mute data rejects loading and preserves the current song.

The existing four-track, 64-clips-per-track, 180-second and bounded undo/audio-memory limits remain in effect.

## Build and run on Windows

From the repository in a Visual Studio 2022 C++ developer terminal, with CMake installed:

```bat
cmake -S . -B build-v12.7 -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=ON
cmake --build build-v12.7 --config Release
ctest --test-dir build-v12.7 -C Release --output-on-failure
"build-v12.7\IDWVoiceMIDIStudio_artefacts\Release\Standalone\IDW Voice MIDI Studio.exe"
```

Configuration fetches the repository's pinned JUCE version; an existing checkout can be supplied with `-DIDW_JUCE_PATH=...`. Audio Lab packaging is separate. Native installer validation has not been completed for this milestone.

## Validation

`IDWSongTakes` exercises all four tracks, direct overlaps and touching endpoints, independent mute and mixer states, source preservation, undo/redo, recovery, primary promotion, copy/split, playback edit locks, new recordings, legacy loading, format-7 corruption rejection and playback/export parity. Recording, clip, fade, arrangement and section regression tests are also run locally, alongside editor/processor syntax checks.
