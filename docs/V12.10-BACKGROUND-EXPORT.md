# V12.10 — background export with progress and cancellation

Full-mix and separate-track WAV exports now render on an owned worker thread. This local source candidate still needs native Windows/macOS, installer, GUI and AudioBox validation.

## Use it

1. Save your song and stop playback/recording.
2. Choose **Export audio > Export full mix WAV** or **Export separate track WAVs**, then choose the destination.
3. IDW captures the current song arrangement and mixer settings. Song Studio shows export progress, and the button changes to **Cancel export**.
4. You may keep editing or resume playback. Those changes do not affect the export already underway. Rendering may compete for CPU/disk resources on slower computers; pause playback if necessary.
5. To stop, click **Cancel export** and wait for cleanup to complete. To keep the export, wait for the completion message and destination path before closing Song Studio.

Only one export runs per panel. Percentage measures rendered audio, not elapsed time; finishing file writes may take longer. Cancel can arrive after a successful final file/folder commit, in which case completion is reported accurately.

## Files and song protection

The worker holds a snapshot with shared immutable source audio, not a reference to the editable live song. Existing takes are retained while needed; recording new material allocates separate buffers. An export can therefore keep old audio in memory after you remove it from the live arrangement. It is not part of the live undo-memory accounting.

Full-mix export uses a temporary file. Cancellation before final commit preserves an existing destination WAV. Stem export stages all five files in a temporary sibling directory and publishes the final folder only after success. Cancellation checks occur between 1,024-sample render blocks and before committing output; cleanup failures are reported. A forced process termination or unexpected error can leave partial temporary files.

Destroying the Song Studio panel requests cancellation and waits for its worker to stop before releasing the snapshot. It does not leave a detached worker accessing deleted UI or song data. Slow or blocked filesystem operations can delay cancellation and closing; cancellation is cooperative, not an interruption of operating-system I/O.

The mix/stem formats and project format are unchanged. See [stem export and DAW import](V12.9-STEM-EXPORT.md) for alignment, printed mixer settings and output-limiter considerations. That guide describes V12.9's synchronous behavior; V12.10 replaces it with this worker workflow. In-progress export is not an autosave; save your song separately.

## Build and run on Windows

With Visual Studio 2022 C++ and CMake, from the repository:

```bat
cmake -S . -B build-v12.10 -G "Visual Studio 17 2022" -A x64 -DBUILD_TESTING=ON
cmake --build build-v12.10 --config Release
ctest --test-dir build-v12.10 -C Release --output-on-failure
"build-v12.10\IDWVoiceMIDIStudio_artefacts\Release\Standalone\IDW Voice MIDI Studio.exe"
```

Configuration fetches pinned JUCE or accepts `-DIDW_JUCE_PATH=...`. Audio Lab packaging is separate. No installed copy is updated by these source changes.

## Validation

`IDWSongExportJob` checks asynchronous mix/stem completion, snapshot isolation from later edits, incremental progress, cancellation before and during export, original-file preservation, staging cleanup, failure reporting and joined worker destruction. `IDWSongStems` checks the existing rendering/output contract. Editor/processor syntax checks cover integration.

Before release, verify progress/cancel at minimum window size and across skins, edit/play while rendering, close during an export, test slow/full destinations and confirm native plugin/installer behavior. Hardware playback quality during export has not been tested here.
