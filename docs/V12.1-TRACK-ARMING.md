# V12.1 — record into any armed track

Local source candidate. A Windows installer and AudioBox hardware validation are still pending. This adds recording to any of the four existing lanes; it does not yet add multiple clips per lane, punch recording, take comping or simultaneous multichannel recording.

## Record a layered song

1. Open **Song Studio**, set BPM and Bars, and import a backing WAV into lane 2 through **Timeline > Import WAV…**. Turn down Beat level if you do not want the built-in drum pattern.
2. Select **1 / Lead vocal**, then click **Arm selected lane**. A dot identifies the armed lane. Selecting another waveform alone does not change the destination. The transport button reads **Record lane 1**; hovering shows its name.
3. Use headphones. Select your microphone input in IDW's audio settings and verify the input meter. With a mono interface input, select the channel containing your microphone. Recording enables IDW microphone monitoring; avoid hearing both interface direct monitoring and software monitoring if they produce an echo.
4. Choose a one- or two-bar count-in if wanted. Press **Record lane 1**, perform, then Stop. Recording starts at bar 1 after the count. Song duration limits recording to the chosen Bars (maximum 180 seconds).
5. Select **3 / Double**, click **Arm selected lane**, then **Record lane 3**. Lead and backing play while only the new processed input is captured. Repeat on lane 4 for ad-libs. Lane 2 can also be recorded if empty.
6. Adjust the recorded clips' start, trim, gain, pan, mute and solo through Timeline, then **Apply track edit**. These mix controls affect monitoring/playback, not the stored input samples. Vocal effects applied before Song Studio remain baked into recordings.
7. **Save song** stores all clips and lyrics. **Export mix WAV** creates a 48 kHz / 24-bit stereo mix. Song files continue using the existing format; V12 can read these recordings. Opening a song resets the armed destination to Lead.

## Protection and troubleshooting

- An occupied armed lane refuses recording. Save first, then use **Remove clip…** in Timeline, **Discard armed clip** in Beat controls, or arm an empty lane. These removal actions require confirmation.
- **Undo track edit** can undo recording, and Redo restores it, within the existing eight-state/512 MiB history budget. History is not saved with the project.
- Arming, clip edits and imports are disabled during playback/count-in/recording. Stopping during count-in captures no audio.
- If an armed track is silent in your headphones, check its Mute/Gain/Pan and other lanes' Solo settings. Muted input is still recorded. Soloing an audio lane silences the synthesized beat.
- Other clips and metronome clicks are excluded from capture internally. Headphones prevent physical microphone bleed.
- Recovery saves stopped songs, not audio from a recording still in progress. Save explicitly before closing.

## Build and test

Use the JUCE/CMake prerequisites described in the existing build documentation. From the repository root, in a fresh build directory:

```sh
cmake -S . -B build-v12.1 -DBUILD_TESTING=ON
cmake --build build-v12.1 --config Release
ctest --test-dir build-v12.1 -C Release --output-on-failure
```

The standalone executable is generated under the build directory's `IDWVoiceMIDIStudio_artefacts/Release/Standalone` folder (platform/configuration dependent). This source change does not install or update an existing Windows copy automatically.

Local validation extends SongArrangementTests across all four recording destinations: arm bounds/transport lock, count-in cancellation, occupied-lane rejection, mono/stereo input, backing exclusion, undo/redo, save/load and immutable recovery snapshots. Existing song, count-in and recovery tests also run. Editor/processor syntax is checked against the available JUCE source. Full native installer builds and listening/latency checks on Windows with AudioBox remain release gates.
